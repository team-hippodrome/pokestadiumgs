## func_80012BC4

This owner allocates from the persistent sample-cache pool at `D_8011F110`.
It returns NULL if `GbApu_Alloc` fails or the cache count equals 1. The
allocation happens before the count check; that second failure path leaves
the allocator's changes in place. On success it marks the indexed entry in
use, stores the allocated address and requested size, increments the cache
count, and returns the entry pointer. The original equality check is retained
without adding another capacity check or rollback.

The existing `AudioSampleCache` view places the allocator at offset 0, its
single 20-byte `SampleCacheEntry` at offset 16, and the signed count at offset
36 (`D_8011F134`). The existing entry fields identify the byte at offset 0 as
`inUse`, the pointer at offset 8 as `allocatedAddr`, and the word at offset
16 as `size`. No new types or storage are introduced.

Compiled `func_80012598` initializes the persistent and temporary pool sizes
and clears their counts. Compiled `func_80012528` selects this owner when its
last argument is nonzero; it fills the returned entry's bank byte, original
medium and sample address, then returns `allocatedAddr`. `GbApu_Alloc`
aligns the requested size, advances the existing pool cursor on success and
increments the pool's own allocation count. These operations establish the
pool, entry and result roles independently of the instruction comparison.
