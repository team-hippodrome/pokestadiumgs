# Audio request sequence

`func_80027634` consumes the byte request set by `func_80028118` and is
called by `func_80027490` while audio updating is enabled. It decrements the
request to select a divisor: mode 4 uses 15, mode 6 uses 18, mode 11 uses 30,
and other modes use 80. While the elapsed counter is below 450, each multiple
of `450 / divisor` increments a signed byte and sends it with command
`0x49000000` through `func_80018728`. A call without a request clears both
counters. Every call clears the request byte. The broader meaning of these
mode values remains unresolved.

The function replaces 80 instructions / 320 bytes at US ROM
`0x28234..0x28374`, retaining its 24-byte frame and original symbol. Its
12-entry switch table now belongs to this source's existing rodata range,
ROM `0xA4590..0xA4660`; the older shared-table prerequisite in
`docs/regions/229E0.md` predates this source split.

The two function-local statics occupy their original addresses:
`u16 sAudioRequestTicks` at `0x800918EC` and
`s8 sAudioRequestValue` at `0x800918F0`. The existing loaded data image
contains their zero initializers. `datamig_bss.ld` places the compiler's
16-byte data section there with NOLOAD; only offsets 0 and 4 are fields,
and compiler alignment adds no loaded bytes or state fields. The original
data labels and loaded data bytes remain intact. A normal full-ROM build
with the assembly body and this storage placement passed before the C body
was installed. File-level statics retain the extern near-match; function
scope recovers the original loads, counter reloads and signed-byte promotion.
