# Region notes — src/340C0.c

## 2026-10-28 — later core compilation unit

This unit contains the GB audio, matrix, rendering, model-animation and
scene-worker functions formerly following VMA `0x800334C0` in
`src/229E0.c`. Shared declarations are in `include/229E0.h`. Historical
per-function source-shape findings remain in `docs/regions/229E0.md`;
look them up by function address or accepted name before probing.

The split preserves the full linked text run and all 578 original function
addresses/sizes across the three units. Normal/blank-prefixed object controls
and the syntax-enabled full retail ROM gate pass. Preserve K&R
`Fragment_ProcessGeoLayout` and its unprototyped declaration: its caller
`func_800416C8` forwards the cached format word with `lw`, while a narrowed
prototype emits `lbu` and changes retail code.

The pre-existing `SWAP_FUNCTION_WORDS` for `func_80039808` moves with that
function. Its genuine C replacement remains future work; this source split
does not establish that this instruction-order workaround has been removed.

## 2026-10-28 — `func_8003F5AC` / `func_8003F6E0`: requeue

requeue. A nickname bonus returning a 4-byte struct by value (hidden `a0`); `func_8003F6E0` takes the species as a third argument instead of `mon[0]`.
- `low = func_8004B920(species, 0)`, `high = func_8004B920(species, 1)`, `result = 0`.
- Species name via `func_800625E0(buf50, species)`, nickname via `func_80060F68(buf40, mon + 0x34)`.
- When `mon[0] != 0xEB` and `HAL_Strcmp(nickname, speciesName) != 0`: a `u8` checksum `(id >> 8) + id` over `*(u16 *)(mon + 6)`, plus every byte of the strings at `mon + 0x34` and `mon + 0x40`, then `result.value = (high - low) * 64 * sum / 255 + low * 64`.
- Stack order: `speciesName[16]`, `nickname[16]`, `result`, `low`, `high`, a named `s8 *storedName = mon + 0x34` passed to `func_80060F68`, then `sum`, `p`, `s8 c`.

Best 0.9744 with the loops written `for (p = mon + 0x34; *p; p++) { c = *p; sum += c; }`; the remaining differences are the `mon + 0x34` spill slot (`0x24` vs `0x28`) and the temp numbering of the checksum seed. The permuter (frame-weighted) went 515 → 435.

## 2026-10-28 — `func_80035620` matched (ROM table load)

Loads 19 words from `D_437620..D_437670` through `func_800042C0` (inside
`main_pool_push_state`/`pop_state('ROMT')`) into `D_80124D00`, the table
`func_800356CC` reads. The copy is a plain `for (i = 0; i < 19; i++)` loop:
copt peels three iterations and unrolls the rest by four. Retail shares one
`lui $at` between the first two peeled stores, which IDO does only for a
symbol it defines, so 340C0.c now defines `s32 D_80124D00[19]`. `rom.yaml`
gives the file its own `.bss` slice at 0x80124D00 (0x4C bytes, padded to
0x50), the rest of `unk_bss4` continues as `unk_bss5` at 0x80124D50, and the
`229E0.h` extern is retyped to `s32[19]`. This is the #1798 mechanism, and
it applies to other shared-`$at` owners whose stores are constant offsets
of one defined symbol.

## func_80033F74 (accepted 2026-10-28)

Channel command handler, dispatched through `D_800921E4[cmd](channel, cmd)`,
so the real signature is `(u8 channel, u8 arg1)`. Retail reuses the
`arg1` parameter to hold `func_800347E8`'s result. Any separate local, of any
type, adds 8 bytes to the frame (0x28 vs 0x20). The non-zero path also needs
`arg1--;` as its own statement before the two stores. `entry[0x20] = arg1 - 1`
puts the decrement in `t0`, and `entry[0x20] = --arg1` moves the `ori`.

## func_800429D8 (accepted 2026-10-28)

PokeIcon bank loader: queues the load (`func_80041FA0` with a zeroed
`Func80041FA0State` by value), waits (`func_800428F8`), then if the bank at
`+0x38` has entries, starts the format-specific transfer and waits again.
Retail masks `arg1` once at entry into a stack-resident `u16` (stored with `sw`,
reloaded with `lhu` from `0x22`), so the parameter is `s32` with a `u16 id`
local. A `resource = arg0` copy is declared between `state` and `format`, and an
`if (!arg0) {} // FAKE` puts `arg0` in `s1` and the bank in `s0`. Without the copy
the id slot is 4 bytes high; without the fake the s-registers swap.

## 2026-10-29: `func_80034838` requeue

requeue (~0.46 by text). This is the GB-audio pitch lookup:
- `packed = (&D_800D2B94)[channel * 0x3C]`;
- `value = D_800925EC[(u16)((packed & 0xF) + arg1)]`;
- shift `value` arithmetically right (`(v >> 1) | (v & 0x8000)`) once per step from `(u8)((packed >> 4) + arg2)` up to 7.

Retail homes all three args (`sw a0..a2, 0..8(sp)`), masks only a0/a1, uses unsigned `srl` throughout, and keeps a sign temp in $v0 on each loop iteration. It never moves the result into $v0, so the caller (`record->unk_18 = ...`) reads a stale value: a missing `return`. We tried prototyped and K&R definitions with u8/u32/s32 typings, separate sign temps, and with and without `return`. Next: K&R definition with `unsigned int` locals and the loop written `while (shift++ < 7)`.
