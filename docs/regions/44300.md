# Record flag predicate

## `func_80044144`

The 72-byte owner reads a signed halfword count at parent offset 2 and a
record pointer at offset 12. It scans that many 36-byte records and returns
zero if bit 0 of any record's leading unsigned halfword is set. It returns
one when every tested bit is clear, including when the count is nonpositive.
It preserves the retail function's lack of a parent-pointer null check.

`func_80043950` in `src/44300.c` selects the same 36-byte record, clears its
leading halfword, and sets bit 0 while populating its other fields. Retail
`func_80043E70` clears that bit in its selected record before advancing the
parent's current index. The new types describe only the header prefix needed
by the predicate and the proven record stride. Other bytes and the function
name retain their unknown forms.

`func_82602930` in `src/fragments/20/fragment20_128B10.c` uses a nonzero
result to advance from state 1 to state 2. Retail `func_86907614` in
`src/fragments/59/fragment59_code.c` also branches on the returned word.
These claims come from inspected C and retail assembly, without runtime
observations or a broader interpretation of the record flag.

The indexed loop retains the signed bound and exits through a result
variable. It compiles to the retail scalar traversal with no stack frame.
Existing matched functions are unchanged.
