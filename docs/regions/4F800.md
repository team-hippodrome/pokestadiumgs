## func_800505A4: requeue (2026-10-28)

Animation cursor step. The cursor is `{s16 frame; s16 index; s32; data *}`, and
`data` is `{u16 flags; u16 count; {s16 duration, s16 value} *entries}`. It
returns `frame + 1` while that is below `entries[index].duration`. Otherwise it
advances `index`; at `count`, flag mask 1 (`flags & 1`) holds the last entry by
stepping back and returning the stored frame. With the bit clear, the index
wraps to zero. Other entry advances return zero. The caller stores the result into `frame`.

Best so far is semantically exact but allocates differently. Retail keeps
`data` in `a1`, `index` in `a3`, the incremented frame in `v1` and
`&entries[index]` in `a2`, and copies `data` into `v0` in the first branch's
delay slot. The else-path then reads `count` through `v0`. Ours puts `data` in
`v0` throughout.

Already tried without gain:
- raw-offset and typed-struct (`AnimFrameCursor`) spellings
- early-return and single-exit shapes
- 180 s of permuter (no structural gain)

Next hypothesis: a different parameter list (unused `a1`..`a3`
parameters would explain the a-register temps), or a separate `entry` local.
