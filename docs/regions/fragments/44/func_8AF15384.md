# Matchup-cell drawing state

`func_8AF15384` emits display list `D_80094E38`, sets render mode
`0xF0A7008`, then selects matching primitive/environment colors and
a texture from the input byte:

| Values | RGBA | Texture word | Resource group / entry |
|---|---|---|---|
| 0, 2 | (0, 200, 200, 255) | `D_8AF33DAC` | 179 / 1 |
| 5 | (200, 200, 0, 255) | `D_8AF33DB4` | 179 / 5 |
| 20, 40 | (200, 0, 0, 255) | `D_8AF33DB0` | 179 / 3 |

Other byte values emit only the initial display-list and render-mode
commands. `func_8AF15F28` loads the three texture words through
`func_8004C990`. The existing word storage is preserved; casts pass the
stored addresses to the actual `s32 func_8004D1FC(u8 *)` interface,
which reads the texture descriptor and submits its image.
//@src/fragments/44/fragment44_2030B0.c
//@src/4CC20.c

Drawing callers `func_8AF15584` and `func_8AF15954`
select this state before drawing cells whose table entries equal the
requested value. The two existing C callers now spell their low-byte
conversion as `(u8)` when calling the byte-parameter definition. This
preserves every instruction in both callers after the prototype becomes
visible. Unknown function and global names remain unchanged.

The replacement matches all 90 instructions / 360 bytes at US ROM
`0x2035F4..0x20375C`, including the 24-byte frame. The compiler generates
the original 41-entry jump table. No new fake, data storage, padding,
helper implementation, or instruction rewrite is required.
